# 每日持仓分析

以仓库策略配置中的资金范围、目标及风险预算为准。用户后续明确修改目标时，保留旧配置并记录新版本及生效日期。不得沿用旧报告的本金、旧定投假设或把建议当成交。

首次使用先运行 `npm run init`。每位用户使用独立本地副本；空白模板不代表已确认策略，`configured:false` 时先确定其目标、配置和风险约束。当前数据接口仅支持公募基金，不把六位股票代码当基金代码查询，也不将基金净值用于场内ETF成交价分析。个人输入、配置、报告及归档均被Git忽略，不强制加入公开提交。

## 日常流程

1. 阅读 `每日持仓.json`、`config/investment-mandate.json`、`data/account/ledger.json` 和上一份日报。先确认快照已保存并校验，日期符合本次请求；保留不同平台的实际持仓记录。
2. 核实当前香港时间及交易时点。通过网络优先读取基金公司、指数提供方、交易所、央行和统计机构的资料；新闻仅作事实发现及交叉核验。更新 `data/research/YYYY-MM-DD.json`，结构参照已有文件或 `docs/daily-analysis-guide.md`；每条证据包含日期、实际公开时间或可靠的首次取得时间、来源URL、事实、解释及适用资产。不得猜测公开时间：只有日期时以首次取得时间限定可用性，记录时间精度。
3. 产品费率、申购限额、暂停状态与渠道相关，按代码及份额核查。旧公告不代表当前实时额度。更新 `config/product-profiles.json` 中的证据及核实时间；财报期与发布日期分开。未披露久期、股票或可转债比例保留未知。
4. 在项目根目录运行 `npm run daily -- --as-of=YYYY-MM-DD`。默认截止时间为本次采集完成时；指定 `--cutoff=ISO带时区时间` 时严守该时点。网络权限受限时按环境审批机制请求对该读取命令的授权；失败仍可使用 `--offline` 生成有明确数据限制的报告。
5. 检查报告的金额、持仓对账、在途资金、批次、额度、费用、回撤计算资格和源数据日期。脚本只输出条件式研究建议，平台下单由用户完成。不得为消除报告警告而自动把未知填0、修改批次区间或确认对账。
6. 审阅当天行情是否支持之前判断，同时记录反证。若需改变策略，修改版本化配置或研究证据并重跑，避免手工改报告数字造成JSON和Markdown不一致。展示首要结论、报告链接、实际限制和每日复用命令。

## 计算与决策规则

- 账户金额由平台记录确定，公开净值不自动覆盖持仓。货币基金万份收益和七日年化不能作为单位净值；未解释金额差额不能反推为申购或收益。
- 股票／黄金基金净值已含基金运作费。产品比较使用分红再投资总收益，个人申赎费另计。最新接口分红金额缺失时，仅可用同代码、同日、同净值且无冲突的已校验归档补全，保留原注释及归档哈希；未知行动不得估算。
- 账户收益需要完整现金流及估值。TWR要求合适的现金流边界估值；Modified Dietz明确为近似。基准前本金不算收益，内部买卖及分红不重复计入外部现金流。账户不足一年不外推年化。真实回撤未知时不使用持有盈亏代替。
- 历史数据没有公开时间时不能声称无前视偏差的择时回测。趋势、相关性、压力场景只是研究证据，用户设定的收益目标和回撤预算都不是保证。
- 同一底层基金／指数风险合并，债券净资产占比大于100%反映杠杆。纯债不等于保本，未披露项不当成零风险。
- 赎回按平台顺序及可赎回份额核算；未到账的钱不能融资新买，未知申购费与限额不能默认免费和无限额。每周额度及冷却只依据真实确认交易扣减。

## 文件与操作

- 最新报告：`docs/reports/YYYY-MM-DD-daily.md`，相邻JSON含结构化结果。
- 每次输入、报告及哈希：`docs/reports/YYYY-MM-DD/<hash>/`。使用 `npm run daily -- --replay=.../inputs.json` 验证同版本可重放；重放不覆盖最新日报。
- 账本字段、对账方法与维护说明见 `docs/daily-analysis-guide.md`。资金或定投资料缺失时照常完成可支持的分析，并清楚标记不能执行或不能核算的部分。

国内利率、上金所行情、官方事件及产品披露目前通过这一步研究流程更新，纯命令运行不会自动撰写新的新闻研究。没有当日研究文件时报告必须显示这一限制。
