# 基金持仓分析工作台

在本机填写持仓、归档公开行情、核算现金流并生成可追溯的每日分析报告。使用 Node.js 22 及以上版本，无第三方运行依赖，不连接交易账户、不执行下单。

## 支持范围

- 支持以人民币记录的公募基金持仓、现金、货币基金收益，以及不同平台的同一基金独立记录。
- 当前查询接口是基金净值接口。**不支持个股、港美股代码或场内 ETF 成交价分析**。六位股票代码可能与基金代码相同，不能直接混填；页面中的“股票型／指数基金”指基金类型。
- 每位用户使用独立的本地副本和配置。没有多用户登录、账户隔离或公网服务能力；本地服务仅监听回环地址。
- 新基金名称可以查询，但分类、穿透、费用和申购状态仍须核查官方资料，写入本地产品配置。无法核实的字段保留未知。

## 首次使用

```powershell
git clone https://github.com/KCFIPR/financing.git
cd financing
npm run init
npm run holdings
```

首次初始化创建空白持仓、账本及本地配置，重复运行不会覆盖已有账户。浏览器打开后添加自己的基金、现金及持仓批次，选择“保存并校验”。Windows 也可在初始化后双击 `启动持仓填写.cmd`。

首次生成报告前，编辑 `config/investment-mandate.json`，明确自己的投资期限、收益目标、风险预算、配置比例、集中度、交易限制以及收益和压力情景假设，再将 `configured` 设为 `true`。示例的全现金比例与零回报是假设占位，不能直接作为投资方案。完善 `config/product-profiles.json` 中自己持有基金的研究证据。不要沿用他人的策略或把样例当作已确认配置。

## 每日使用

更新持仓并保存校验后运行：

```powershell
npm run daily
# 明确日期和截止时间，仅使用当时已知的本地数据
npm run daily -- --as-of=YYYY-MM-DD --cutoff=YYYY-MM-DDT17:30:00+08:00 --offline
# 使用冻结输入和同版本代码重放
npm run daily -- --replay=docs/reports/日期/输入哈希/inputs.json
npm test
```

报告写入本地 `docs/reports/日期-daily.md`，并保存结构化结果、证据及代码哈希。自动采集基金净值、货币基金收益和 FRED 序列。国内收盘、利率、黄金、产品公告等人工研究，可请求助手应用 [每日复盘 Skill](skills/portfolio-daily-review/SKILL.md)。单独运行命令不会自动撰写新闻研究，缺少证据时报告明确降级。没有后台定时任务。

详细流程见 [每日分析指南](docs/daily-analysis-guide.md) 和 [持仓填写指南](docs/holdings-editor-guide.md)。

## 数据与隐私

以下文件只存于使用者本机，已加入 `.gitignore`：

|本地路径|用途|
|---|---|
|`每日持仓.json`|唯一日常可编辑持仓输入|
|`data/`|正式快照、历史输入、流水账本、行情、研究和原始证据|
|`config/investment-mandate.json`|个人目标、风险预算及配置策略|
|`config/product-profiles.json`、`config/documents.json`|自选产品及研究资料|
|`docs/reports/`|每日分析报告和冻结输入|
|`archive/`、`REVIEW.md`|个人历史归档和本地审阅入口|
|`持仓填写.html`|从通用源码生成的本地页面|

公共仓库保留 `config/examples/` 中的空白模板、通用页面源码、脚本、文档和合成测试数据。页面不内嵌账户信息，不显示旧持仓金额占位提示；真实数据只通过本机服务加载。查询基金名称和采集行情会将所查询的基金代码发送给数据提供方，不发送账户金额和盈亏。

Git 忽略规则不会自动保护另存到其他位置的文件，也不会清除已经提交过的历史。分享或提交前检查暂存内容，不要强制添加上述私有文件。每个人应自行备份未纳入 Git 的账户资料。

## 核算边界

外部入金不算收益，内部申赎不算外部现金流，建议不算成交。行情不会覆盖平台金额。只有账户估值与现金流完整时才计算相应绩效；不足一年的账户不展示短期外推年化。分红、拆分无法确认时只展示价格，不冒充总收益。收益目标和回撤预算均不构成保证。
