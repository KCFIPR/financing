# JSON持仓填写与保存

日常只维护项目根目录的 `每日持仓.json`。页面不再内嵌seed，也不从浏览器localStorage恢复数据；每次打开或点击“重新读取JSON”，都直接读取该文件。

## 打开页面

双击 `启动持仓填写.cmd`，自动启动本地服务并打开浏览器。保留服务窗口，关闭窗口即停止服务。也可在项目目录运行：

```powershell
npm run holdings
```

然后访问 `http://127.0.0.1:8765`。普通浏览器直接双击HTML无法写回项目文件，请使用启动入口。本服务无需安装依赖，仅监听本机。

## 填写

- 查看日期、实际策略可用现金和纳入分析的每笔持仓当前金额是正式保存的必填项。已卖完可以金额填0并删除旧批次，也可直接删除投资记录。
- 每笔投资填写“持有收益（元，选填）”，直接抄平台当前持仓数据，亏损填负数，未知留空。JSON保存为`holding_pnl_cny`，空值为`null`；草稿、正式快照及重新读取均保留，暂不分析的投资也可记录。页面不再提供累计收益输入。
- “持有收益率（%，自动估算）”只读，无需自行计算。按`持有收益 ÷（当前持有金额 − 持有收益）× 100%`计算，输入金额或持有收益时实时更新，保存时重新计算为`estimated_holding_return_pct`。例如金额1100元、持有收益100元，推算成本1000元，估算收益率10%。金额或持有收益未知、推算成本不为正时留空。分红、费用等可能使推算成本与平台成本不同，因此标为估算，不视为平台报告值或年化收益率。
- 平台若显示持有收益率，可在“平台持有收益率（可选，用于核对）”中直接抄录，百分数`-1.25`代表`-1.25%`，保存为`holding_return_pct`。之前填写的值保留在这里，自动估算不会覆盖。
- 历史累计收益不会自动当作当前持有收益，归档记录保留。更新查看日期时请核对持有收益；它不额外计入资产合计，缺少交易现金流时不计算年化收益。
- 每个买入批次填写份额、截至查看日期的持有天数、当前赎回费率。`0.5`代表`0.5%`，`0`代表免赎回费。未知留空；JSON中保存为`null`。
- 持有天数分为“最少天数（含）／最多天数（含）”两个输入框，两端都包含。7至59天填`7／59`；至少60天填`60／留空`；不足7天填`留空／6`；确切60天填`60／60`；未知两框留空。端点须为非负整数，下限不能大于上限。JSON保存为`holding_days_min`和`holding_days_max`两个数字字段，空值为`null`，不再写入`holding_days`。
- 旧JSON中的单一天数和区间会在读取时自动转换，例如`60`变为`60／60`，`>=60天`变为`60／null`，`<7天`变为`null／6`，`>60天`变为`61／null`。保存后使用新字段，历史文件保留。区间不会被推定为某个具体天数或持有起始日期。
- 不要求持有起始日期。默认全部已填份额可赎回；有锁定或冻结份额时取消勾选，填实际可赎回份额。
- 正式单位净值可选；填写时必须提供实际净值日期，不能用查看日期或盘中估算值替代。
- 待确认款没有时填0，未知留空；同一款项不能在基金和现金中重复记。待确认款不会自动加入资产合计。
- 首次运行npm run init创建空白JSON，不包含任何示例持仓；日期、现金和基金金额由使用者填写。重复初始化不会覆盖已有文件。

页面和服务端共用JSON校验规则，包括编号唯一、六位基金代码、名称和平台、日期、数字、持有天数及区间、费率百分数范围、份额一致性。更新日期后请核对持有天数和费率，页面不会自动推算未来费用档位。

## 新增、删除和分析范围

- **添加投资**：填写六位基金代码、名称（含A/C类）、平台和类型。编号自动生成；同一基金可以在多个平台或账户分别记录。支持原清单以外的新基金，不需要修改代码或固定白名单。
- 输入完整六位基金代码后，页面自动通过本地服务查询天天基金（东方财富）名称并填写，保留A/C类别；可手动修改。修改代码会清空上一代码的名称并重新查询，旧查询结果不会覆盖新代码或查询期间手动填写的名称。查询失败可以点击“重新查询”或手动输入；平台仍需自行填写。查询需联网，成功结果在当前服务进程内缓存24小时。
- **编辑投资信息**：每项投资展开“编辑投资名称、代码、平台与类型”即可修正。换代码或平台后，不沿用旧标的的历史收益数字。
- **纳入分析**：取消勾选可暂时排除不参与本次分析的基金，记录和批次仍保留在填写JSON。金额与批次可留空；已填写的数字仍须有效。重新勾选后可恢复。
- **删除投资**：确认后从页面移除，保存后写回JSON。保存前可重新读取撤销，保存后可在历史JSON中找回。删除不被推定为卖出，不自动增加现金或计算收益。
- 顶部可筛选“全部记录／纳入分析／暂不分析”。金额合计只计算纳入分析的投资；可用现金仅指纳入本策略的现金。
- 分析范围的变更在“保存并校验”后生效。正式快照的`holdings`只包含纳入分析的记录，`excluded_holdings`保留暂不分析项，`removed_holding_ids`记录本次移除的编号。数据采集与状态检查读取分析范围内的`holdings`，暂不分析项不会加入策略金额、采集或缺失信息提示。

## 保存

- **保存草稿到JSON**：允许日期、金额、现金或批次尚未填完。已填值须合法。直接写回`每日持仓.json`，状态为`draft`，不会改动正式分析快照。
- **保存并校验**：全部必填项合法后写回JSON，状态为`validated`，同时更新`data/holdings/current.json`。批次、份额、天数和费率保留为结构化字段，无需经过CSV。
- **重新读取JSON**：读取磁盘当前数据；若页面有未保存修改，会先提示。可直接用编辑器修改JSON，再重新读取。
- **下载JSON备份**：仅为额外备份，日常保存不需要手工复制下载文件。旧页面导出的JSON仍可通过“载入JSON文件”载入，然后点保存。

输入不会自动保存；离开页面前请点保存。两个窗口或外部编辑器修改同一JSON时，旧窗口保存会提示版本冲突，避免覆盖新数据。服务正在保存时页面暂时禁止编辑。

更新页面代码后，原来运行的Node服务仍可能使用内存中的旧校验逻辑，需要关闭原服务并重新启动。页面读取及保存前都会核对服务版本；若是旧服务，会阻止保存并保留页面中未保存的内容，避免新字段被静默丢弃。新版服务也会拒绝旧页面的保存请求，此时刷新页面使用新版。

每次保存前保留上一版填写JSON到`data/holdings/input-history/`。正式校验后的原始JSON和分析快照另存到`data/raw/holdings/`及`data/holdings/history/`。校验失败不会覆盖数据。`current.json`是派生的分析结果，不需要手工维护。

## 手动校验

```powershell
node scripts/snapshot.mjs check
node scripts/snapshot.mjs import
```

默认处理`每日持仓.json`；纳入分析项未完成的草稿无法导入正式分析。也可显式指定另一份JSON路径，投资项通过页面直接添加和删除。

页面代码修改后运行`node scripts/build-holdings-editor.mjs`重新生成HTML。重建页面只更新代码，不读取或覆盖填写JSON，修改数据无需重建页面。
